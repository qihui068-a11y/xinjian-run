## 对报告的三点异议

1. **P0#1「控制指令只接受已通过验证的好友」对「同意」不适用**：同意本身就发生在成为好友之前，
   加了这条会把验证流程锁死。改成「精确匹配 + 必须正处于等待该 peer 的状态」，等价强度、不破坏流程。
2. **M2 完全下推原生不建议现在做**：要么改协议（原生先问 JS 收不收），要么把好友表复制一份到原生，
   两条都会让状态出现两个真源。这轮用「落盘后立即删」消掉存储与可访问性影响，带宽问题留到做限速时一起。
3. **M8 按 IP 限速在家庭 NAT 下会误伤**：同网设备通常共享一个公网出口，按来源 IP 限速会把整户限掉；
   真要防 DoS，更合适的是按 `xj-id` 计数（需要 H2 的身份可信才成立）。

## 新增测试（5 项，专盯本报告）

- 控制信号必须精确匹配、终止只认好友、非等待态不认同意
- 被屏蔽者的图片会被删盘且不进会话
- 删联系人会连带删除该会话的图片文件
- 选「保留」后不再弹窗（`termAck`）
- 纯图片会话摘要显示「[图片]」、发消息前剥掉控制字符
