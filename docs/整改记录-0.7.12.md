## 开工 H2/H4 前要定的三件事

（上一版这里引用了一份并不存在的「交付说明」，链接是断的。按要求把内容直接写进来。）

### ① 身份模型：设备密钥 还是 好友间共享密钥

- **A（推荐）每设备一对长期密钥**（P-256 或 Ed25519），加好友时交换公钥并绑到 `xj-id`。
  好处：一台设备对多个好友只维护一份身份，将来做群聊也成立。
- B 每对好友 ECDH 协商一个对称密钥。实现更简单，但好友一多就是 N 份密钥，群聊要重设计。

### ② 兼容策略：硬切 还是 软降级

- **A（推荐）硬切**：v2 只与 v2 通信，遇到 v1 设备在列表里显示「对方版本过旧」。
  边界干净，用户不会误以为自己「加密着聊」。
- B 软降级：v1 仍可明文聊，UI 标「不安全」。保留兼容，代价是给自己留了一条可降级的路——
  降级攻击的教科书入口。

### ③ 完整性范围与重放

- **A（推荐）文本与控制帧全签；图片块只签头部**（`mid/seq/total/size`）+ 整图校验和。
  每块都签会让 CPU 与带宽翻倍，收益很小——图片内容最终由整图校验和兜底。
- 重放防护：`mid` + 单调 `seq` + 5 分钟时间窗 + 去重表；现有 `mid` 去重可复用，加时间窗即可。

> 这三条定下来，实现路径就唯一了：密钥交换（①）+ 版本协商（②）+ 帧签名（③）。剩下的都是工程量。
