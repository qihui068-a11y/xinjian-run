## 四、天气

### 形态

- 主页面顶部，与底栏互不干涉
- **折叠态**：全屏高度 1/10（约 70dp）单行横条，纯色底，不显示背景图
  - 内容：城市 · 温度 · 天气 · AQI
- **展开态**：点击展开大卡片，再点收回，卡片显示背景图
  - 内容：大温度、天气文字、风级、预警（若有）、体感、湿度、更新时间、城市名（可点击）

### 数据源优先级

| 链 | 顺序 |
|---|---|
| 主链（温度/天气/风/湿度/更新时间） | 中国天气网 → 和风 → 高德 → Open-Meteo（兜底） |
| AQI 链 | 和风 → 高德 → Open-Meteo |
| 预警链 | 和风 → 高德（全失败则整块隐藏） |

- 降级判据：超时 > 5s / HTTP 非 200 / 解析失败 / 关键字段缺失 / 语义错误码 / AQI 为空
- 冷却：额度类错误冷却至次日 00:00；网络与解析类错误冷却 30 分钟
- 中国天气网为非官方接口，伪 JSON + GBK + 需 Referer，全部由原生层处理

### 刷新

- 仅在处于主页面且 App 前台时，每 10 分钟检查一次 `obsTime`
- `obsTime` 未变则不重绘（实际请求约每小时一次）
- 冷启动先渲染缓存再后台刷新；离线维持上次数据并标注「离线」

### 单位

- ℃ / ℉ 切换置于设置，持久化

### 背景图（14 张）

- 7 类天气 × 昼 / 夜：晴、多云、阴、雨、暴雨雷暴、雪、雾霾
- CSS 渐变 + SVG 多层模糊程序化生成，零体积、无版权
- 保留 `imageSource` 字段，未来可换实拍图

### 城市

- 首次申请 Android 定位权限，GPS 自动定位
- 内置城市库：地级市 + 县级约 2900 条，含拼音首字母，约 180KB
- 城市选择页：顶部搜索框，右侧 A-Z 索引条，右上角「恢复自动定位」，无热门城市
- 手动选定后写入本地偏好，不再被 GPS 覆盖

## 十三、鸽屋（通讯，前端占位）

定位：**双人通讯**，将来要接服务器。当前是**纯前端占位，完全不联网**。

### 层级

小家（一级）→ 鸽屋（二级，会话列表）→ 会话（三级）

**一个会话 = 一个联系人。** 暂不单独建好友表（通讯录先按这个来）。

### 会话列表

右上角 `+` 展开下拉气泡菜单（深灰气泡，右上角小三角指向 `+`）：

| 项 | 行为 |
|---|---|
| 发起群聊 | 三级占位页 |
| 添加朋友 | 底部输入框，自动 `focus` 唤起输入法；输入内容当作会话名，建好后直接进会话 |
| 扫一扫 | 三级占位页。**相机已经能调了，但没有识别库**，所以仍只显示文案 |
| 收付款 | 三级占位页「暂未开始发展此业务哦~」 |

菜单**占返回键一层**：菜单开着时按返回键只关菜单，不会退出鸽屋。

### 内置 NPC：FUO

- 默认预置一个会话 `FUO`，本地对象，永不联网
- 一进去就有一句开场白：**「你好，我是FUO。」**
- 发任何内容，420ms 后回同一句；发几条回几条
- 自己的消息在右侧，标「本机 · 未送达」
- 420ms 是故意留的：瞬间回复读起来像自问自答

### 数据

- 现在存 `localStorage['xj:pigeon:v1']`，独立命名空间，**不进书架**
- 结构预留：

```
{
  order: [sid],
  sessions: {
    sid: { id, name, npc, mtime, msgs: [ ... ] }
  }
}
```

- 接服务器时**只替换 `Pigeon` 模块**，视图不用动
- 消息有 4 种形态，靠 `kind` 区分；**老数据没有 `kind`，一律当文字**：

```
文字  { text, dir, t }
图片  { kind:'image', name, size, dir, t }
文件  { kind:'file',  name, size, dir, t }
位置  { kind:'loc',   lat, lon, acc, fine, dir, t }
```

- 图片和文件**只存文件名，不存内容**。内容落在私有目录 `media/`。
  绝对不能把 base64 塞进 `localStorage`——WebView 那块上限只有 5~10MB，
  一张照片就能把整个鸽屋挤爆
- `dir` 仍是 `in / out`。**群聊需要 `sender` 字段，仍未加**

- 群聊（要改消息模型，缺 `sender`）
- 扫一扫（相机已能调，**缺识别库**）

## 十四、权限（已实现）

清单里一共 **8 条**：

| 权限 | 用途 | 类型 |
|---|---|---|
| `INTERNET` | 鸽屋收发（以后） | 普通，安装即授，用户无法拒绝 |
| `ACCESS_NETWORK_STATE` | 判断有没有网 | 普通 |
| `CAMERA` | 拍摄；以后的扫一扫 | 危险，运行时申请 |
| `ACCESS_COARSE_LOCATION` | 发位置（城市级） | 危险，运行时申请 |
| `ACCESS_FINE_LOCATION` | 发位置（街道级） | 危险，运行时申请 |
| `READ_MEDIA_IMAGES` | 以后的头像 / 背景板存图 | 危险（13+），现在还用不上 |
| `READ_EXTERNAL_STORAGE` | 同上，Android ≤12 | 危险，`maxSdk=32` |
| `WRITE_EXTERNAL_STORAGE` | 导出到公共目录，Android ≤9 | 危险，`maxSdk=28` |

**存储权限明确保留**：以后要把图片、备份存到公共位置。现在用不上不等于不要。

其它硬约束：

- `CAMERA` 必须配 `uses-feature android:hardware.camera required="false"`，
  否则没有相机的设备连装都装不上
- 版本分支全部在原生：`>=33` 用 `READ_MEDIA_IMAGES`，否则 `READ_EXTERNAL_STORAGE`；
  `<23` 视为安装即授予
- 相册和文件**走系统选择器，不需要存储权限**。这是故意的：
  不授权也能发图发文件，权限页的说明也这么写

### 权限页（三级）

展示 5 行：网络 / 照片和视频 / 相机 / 大致位置 / 精确位置。

- 网络是普通权限，**不显示申请按钮**
- 位置两条**分开申请**。申请「精确」时同一请求里必须带上「大致」（Android 12+ 强制），
  用户可以只给大致；这时回调**如实返回 `false`**，界面不许谎报成功
- 申请「精确」只给了「大致」的情况下，发位置仍然要能走通（回落到大致的精度）

### 「关闭」按钮 = 跳系统页（重要限制）

第三方应用**无法**用代码撤销自己已授予的运行时权限
（`revokeRuntimePermission` 是 `@SystemApi`，要系统签名）。

所以实现只有一条路：

1. 已授权、且支持撤销的行，右侧显示「关闭」
2. 点击 → 打开系统的「本应用权限页」（`ACTION_APPLICATION_DETAILS_SETTINGS`）
3. 用户在那里点掉 → 回到 App，原生 `onResume` 喊 `window.__xjPermRefresh()`
   → 页面重新读真实状态

**一句话：关闭动作是真的，但必须在系统界面上完成，App 不能代劳。**

### 回调契约

- 发起：`XinJianBridge.askPerm(key)`，`requestCode`：1002 相机 / 1003 存储 /
  1004 大致位置 / 1005 精确位置
- 收结果：`MainActivity.onRequestPermissionsResult`
  （这个方法在本轮之前**根本不存在**，P0-4 那次权限申请完没人接结果）
- 回传：`runOnUiThread` + `web.evaluateJavascript("window.__xjPerm(key, ok)")`
- Web 侧：视图挂载时设 `window.__xjPerm`，离开时置 `null`

## 十五、会话里的媒体消息（已实现）

### 面板四项

会话页右下角那个按钮是动态的：

| 输入框 | 按钮 | 点击 |
|---|---|---|
| 空（含只有空格） | 圆形 `+` | 展开功能面板 |
| 有字 | 「发送」 | 直接发出，不弹面板 |

面板只保留四项：**相册 / 拍摄 / 位置 / 文件**。
（收藏、音乐、个人名片按需求删掉了，不要加回来。）

| 项 | 实现 |
|---|---|
| 相册 | `PICK_IMAGES`（33+）/ `GET_CONTENT`（旧版）→ 复制到私有目录 → 图片气泡 |
| 拍摄 | 先查相机权限（没给就申请，授权后**自动接着拍**）→ 系统相机 → 图片气泡 |
| 位置 | 先查位置权限 → `LocationManager` 单次定位（8 秒超时）→ 位置卡片 |
| 文件 | `OPEN_DOCUMENT`（任意类型）→ 复制到私有目录 → 文件卡片 |

面板的细节（照微信）：

- 打开面板先收键盘
- 发消息时面板自动收起
- **面板占返回键一层**：按返回只收面板，不退出会话

### 落盘

- 位置：`/sdcard/Android/data/tt.xinjian.cn/files/media/`，**卸载即失**，和书架同策略
- WebView 通过 `https://app.xinjian.local/media/文件名` 取图，
  由 `shouldInterceptRequest` 拦下来直接返流（带路径穿越防护：拒 `/` 和 `..`）
- 重名自动加 `_1 _2`

### 为什么不用 FileProvider

没有 AndroidX，用不了 `androidx.core.content.FileProvider`。
拍照输出改成先用 `MediaStore` 插一条记录拿 `content://`，
再用 `EXTRA_OUTPUT` 交给相机写。29+ 免存储权限。

**坑**：清单里声明了 `CAMERA` 却还没授权时，`ACTION_IMAGE_CAPTURE` 会直接抛
`SecurityException`。所以拍照前必须先挡一道权限检查。

### 位置的先天限制

没有 Play Services，也不联外网做逆地理编码，**只能拿到经纬度，拿不到地名**。
卡片显示：`北纬 30.2741°, 东经 120.1551°`。要地名得以后接服务。

### 异步回调

四个入口都是「调完立刻返回，结果异步回来」：

- 选图 / 拍照 / 选文件 → `window.__xjPick(json)`
- 定位 → `window.__xjLoc(json)`
- 失败也回调，带 `why`：`cancel` / `perm` / `copy` / `timeout` / `nopicker`

Web 侧有个模块级 `ChatSink`，会话页挂载时注册、离开时置空。
**迟到的回调不能打到已经离开的界面上。**

## 十六、深色主题与原生窗口（已实现）

### 三处白底，逐个处理

「深色模式下还是白」其实有三个不同的来源：

| # | 来源 | 处理 |
|---|---|---|
| 1 | Activity 窗口底色（`Theme.Material.Light`） | 原生按偏好动态改窗口底色 |
| 2 | `html` 画布层一直是白 | 深色变量同时挂到 `html.dark` |
| 3 | 冷启动第一帧是启动窗口 | 新增 `XjLaunch` 主题，底色 `#1E1E1E` |

### 原生跟着 Web 走

- Web 切主题 → `Bridge.theme('1'/'0')` → `MainActivity.applyTheme()`
- 一起改：窗口底色、WebView 底色、状态栏、导航栏、状态栏图标明暗
- 同时写进 `SharedPreferences('xj').xj_dark`，
  冷启动时在 WebView 起来之前就刷对底色，深色用户不会先闪一下白
- `setStatusBarColor` / `setNavigationBarColor` 需要
  `FLAG_DRAWS_SYSTEM_BAR_BACKGROUNDS`，某些机型不加不生效

`#1E1E1E` 必须和 `style.css` 里的 `--bg` 一致，改一个要改两处。

### html 画布那个坑（值得记住）

```css
:root{ --bg:#FFFFFF; }
body.dark{ --bg:#1E1E1E; }     /* 只挂在 body 上 */
html,body{ background:var(--bg); }
```

CSS 变量只往下继承。`--bg` 写在 `body` 上，`html` 是它的**父节点**，
取不到这个值，于是 `html` 的底色一直是 `:root` 的白。
而 `html` 就是 WebView 画布那一层。

现象很怪但很一致：**只有会话页、只有键盘收起时闪白**。
因为 `.view` 是 `position:fixed;inset:0`，平时盖着画布；
视口变高那一两帧跟不上，底部就露出 `html` 的白。键盘弹出时视口变小，
旧的较大尺寸反而盖得住，所以不闪。

修法：深色变量改成 `html.dark, body.dark` 双挂，并在 JS 里把
`document.documentElement.style.backgroundColor` 直接写成内联色（双保险）。

### 启动窗口

`res/values/styles.xml` 里定义 `XjLaunch`，只给 `MainActivity` 挂：

- `windowBackground` = `#FF1E1E1E`（Android 11 及以下就是它）
- `windowSplashScreenBackground` = 同上（Android 12+ 系统 Splash）
- `statusBarColor` / `navigationBarColor` = 同上，图标用浅色
- 父主题仍是 `Light`，对话框保持浅色，不受牵连

> XML 注释里**不能出现 `--`**。写 CSS 变量名 `--bg` 进注释会让 aapt
> 报 `not well-formed (invalid token)`，注释被提前截断。

### 已知未处理

- **对话框还是白的**：添加朋友那个输入框、`AlertDialog` 走 Light 主题，
  深色模式下是一块白。要修得起 DayNight 主题或给对话框单独配色
- 启动帧固定深灰。若用户把 App 主题设成洁白，冷启动会看到「深灰→白」一瞬。
  彻底贴合个人偏好做不到：启动窗口在进程启动之前就画完了，那时读不到 App 内设置

## 十七、Markdown 阅读态（已实现）

`.md` 在**阅读态**渲染成排版后的文本；**编辑态**仍然是原始源码。
`.txt` / `.bf` 行为不变。

### 文件

`app/md.js`，纯手写、离线、无任何第三方库，暴露 `window.MD.render(text)`。

> `build.sh` 的资源是**写死的文件清单**（变量 `WEBFILES`，现为 17 个文件：
> `index.html style.css bridge.js highlight.js md.js anim.js navindicator.js themereveal.js
> app.js data.js boot.js views/{home,shelf,create,editor,me,chat}.js`）。新增任何前端文件都要记得加进去，
> 否则测试全绿、装机即崩（`MD is not defined`）——测试读的是 `/sdcard/信笺/app/`，
> 而包里只有清单里的文件。
> **这个坑已经踩过三次。** 另外 `views/` 是子目录，`cp` 前必须
> `mkdir -p "$OUT/assets/www/views"`，否则 `cp` 直接失败（`aapt` 会把缺的文件
> 静默漏掉，表现仍然是装机即崩）。

### 支持的语法

| 语法 | 输出 |
|---|---|
| `#` ~ `######` | `<h1>`~`<h6>`，带 `id` 锚点 |
| 段落 / 空行 | `<p>`，段内单换行 → `<br>` |
| `**粗**` `__粗__` | `<strong>` |
| `*斜*` `_斜_` | `<em>` |
| `~~删~~` | `<del>` |
| `` `代码` `` | `<code>`（先摘出，内部星号不会被当强调） |
| ` ```lang ` | `<pre class="md-code" data-lang="lang">` |
| `> 引用` | `<blockquote>`（内部递归解析） |
| `-` / `*` / `+` / `1.` | `<ul>` / `<ol>`，缩进 ≥2 空格算嵌套 |
| `---` | `<hr>` |
| `[字](url)` | `<a href>` |
| `![alt](src)` | `<img>`（优先于链接解析） |
| `\| a \| b \|` + 分隔行 | `<table class="md-table">` |

### 安全：先转义再解析

`inline()` 第一行就是 `s = esc(s)`，把 `& < > "` 全部转义，之后才做语法替换。
自插入的标签永远是我们自己的常量，用户内容永远是转义后的值。

这条**必须有测试盯着**：第一版 `inline()` 漏了这句，4 条注入测试立刻全红
（`<script>` 能原样穿过、`alt="a" onerror="…` 能撑开属性）。现在 `tests/md.js`
里有 4 条专门守它。

> 引号实体不要写成字面量：在多层工具链里会被解码成 `"`，等于没转义。
> 现在用 `var QUOT = '&' + 'quot;';` 拼接生成。

### 目录跳转

小说文件的目录通常是 `[第一章　风雨欲来（上）](#第一章风雨欲来上)`，
而标题文本是 `第一章　风雨欲来（上）`。两侧都过 `MD.slug()`（去掉空格、标点、
全角括号，只留中日韩文字与字母数字）再比对，就能对上。

- 点击 `href` 以 `#` 开头的链接 → 在渲染容器里找标题，`scrollIntoView`
- 非 `#` 链接**不跳**，只提示「外部链接暂不打开」（WebView 里跳出去就回不来了）
- 找不到就提示「找不到这一节」，不静默

### 阅读态与源码视图的切换

同一个视图里两个容器互斥：

```
.md-view（渲染结果，阅读态显示）  ←→  .editor-wrap（gutter + pre + textarea，其余情况显示）
```

- 阅读态：`#stPos`（行:列）隐藏，因为没有光标；字数照常显示
- 编辑态：一切照旧，`textarea` 里是原始 markdown，改完点「完成」→ 重新渲染
- 重命名把 `.md` 改成别的扩展名时，`isMd` 要重新算，并重跑 `setMode`

### 已知未做

- 表头对齐（`:-:`）没实现，一律左对齐
- 表格超宽时不横向滚动（只做了 `border-collapse`，没套滚动容器）
- 没有首行缩进。中文小说常见 `text-indent:2em`，但通用 md 文档加缩进会怪，
  要的话给 `.md-body p` 加一行即可
- Setext 标题（`===` / `---` 下划线式）不支持
- 脚注、任务列表 `- [ ]`、定义列表都不支持

## 十八、微交互动效（第 1 批已实现）

参照 *Advanced Interaction Design* 的 10 种交互模式。**只做微交互，不做页面转场**
（转场另开一轮）。

### 基础设施

`app/anim.js`，离线无依赖，暴露 `window.Anim`：

| 方法 | 作用 |
|---|---|
| `Anim.enabled()` | 当前是否允许动效（用户开关 + 系统偏好，两者都挡） |
| `Anim.setEnabled(on)` | 写 `localStorage['xj:anim'] = 'on' / 'off'` |
| `Anim.stagger(nodes, {step})` | 错峰入场，默认从下往上 |

> `Anim.ripple` 和整套点击泛光已在 2026-11-24 按用户要求**整体删除**——
> 只留 `stagger` 一种效果。下面「第 1 项」保留删除记录，不删档，以免以后又加回来。

三档时长（文档只要求「具体」，这个数值是我们定的）：
**微反馈 180ms / 位移 240ms / 主题级 420ms**。

三条不能破的规矩：

1. **只动 `transform` / `opacity` / `max-width`**，不动 `left/top/width/height`，
   避免逐帧重排。唯一例外是滑动指示条（第二十节）——它本来就得动 `left/width`，
   且同一时刻只有一条在动。
2. **动画结束后 DOM 的最终状态和「没有动画」完全一致**。做法是「先落终态、再补动画」，
   并且动画跑完就把动画类摘掉。测试和不确定性都靠这条压住。
3. **必须能关**。`设置 → 动效` 有开 / 关；系统 `prefers-reduced-motion: reduce`
   也会强制不动（CSS 层和 JS 层各挡一次）。

> 关掉动效时**不是把时长设成 0**，而是直接走「只落终态、不加动画类」的分支，
> 所以不会出现「元素停在半透明中间态」。

### 第 1 批原本做了三种，现在剩两种

#### 1. ~~Ripple Feedback（全局）~~ —— 已删除

用户反馈「点击泛光」不喜欢，**整套删掉**（2026-11-24）。删掉的东西：

| 位置 | 内容 |
|---|---|
| `anim.js` | `ripple()` / `layerEl()` / `ripple-layer` 层 / 导出表里的 `ripple` |
| `boot.js` | 全局 `pointerdown` 捕获委托 + `.book` 的 `click` 捕获补波纹（**这两个监听全没了，boot.js 现在只做首屏渲染**） |
| `style.css` | `.ripple-layer` / `.ripple` / `@keyframes xjRipple` / reduced-motion 里的 `.ripple` |
| `views/shelf.js` | 长按成功时「在卡片中心补一圈波纹」的确认反馈 |

副作用（都是好的）：

- **长按的死因 2 从根上消失了**。原先的修法是「把 `.book` 挪到 click 阶段补」，
  现在连补偿都不需要——按压过程一个节点都不插（`tests/longpress.js` 里守着这条）。
- 长按成功的确认反馈只剩「`.stg-run` 错峰升起 + 顶栏计数变化」。

#### 2. Staggered Block Selection（书架多选）

- 触发：长按进入多选（所有格子错峰）／点选某一格（只动那一格）
- 顺序：**从下往上**，最后一格延迟 0，往上每格 +40ms
- 每格：`translateY(10px) + scale(.97) + opacity .35` → 归位，240ms
- 选中态仍用**描边**（`border-color` + 勾选圈），**不用填充**，格子和文字都不变暗
- 延迟通过 CSS 变量 `--stg-delay` 传递，跑完摘掉 `stg-run`

#### 3. Expanding Tag Selection（新建页的格式胶囊）

- 选中胶囊**展开**，露出扩展名（`.md` / `.bf` …），未选中缩回
- 展开靠 `max-width: 0 → 5em` + `opacity`，220ms `cubic-bezier(.2,.8,.2,1)`
- 按下时整体 `scale(.96)` 给手感

> 这条的**关键前提**是胶囊节点不能重建：原本 `paintChips()` 每次选择都重写
> `innerHTML`，节点被换掉，`transition` 永远播不出来（新节点没有起始状态）。
> 改成「只建一次，之后只切类」。设置页的动效开关踩过同一个坑，已一并改掉。

### 踩坑：第 1 批动效把书架长按搞没了（已修）

上了第 1 批之后用户反馈「长按没有多选了」。**主因是波纹，另外还暴露出一个一直存在的抖动问题。**

#### 死因 1：`pointermove` 没有容差（真正的元凶）

原来的写法是：

```js
['pointerup', 'pointercancel', 'pointermove', 'scroll'].forEach(ev =>
  grid.addEventListener(ev, () => clearTimeout(pressTimer)));
```

真机手指「按住不动」时，系统仍在持续派发 1~4px 的 `pointermove`，
任何一次都会 `clearTimeout`，600ms 永远熬不到，长按必然失效。

> **为什么测试没抓到**：jsdom 不会像真机那样发抖动 `pointermove`。
> `tests/anim.js` 里那条「长按进入多选」在旧代码上也是绿的——**是假阳性**，
> 它证明的是「没有 move 时长按会触发」，不是「真机上长按会触发」。

修法：按下时记起点 `pressFrom`，独立一个 `pointermove` 监听，
只有位移**平方**大于 `PRESS_SLOP²`（8px）才取消。
`pointerup` / `pointercancel` 仍无条件取消。

#### 死因 2：波纹插在长按手势中途

波纹原来挂在全局 `pointerdown`，`.book` 也在选择器里。按下瞬间往触点插入一个
`<span class="ripple">`，部分 WebView 认为「手势期间 DOM 变动」而派发 `pointercancel`，
把计时器一起掐掉。

当时的修法是「`.book` 挪到 `click` 捕获阶段补 + 长按成功在卡片中心补一次」。
后来点击泛光被整套删除，这个死因**从根上没有了**：现在按压过程一个节点都不插，
`boot.js` 里也不再有任何 `pointerdown` 监听。

#### 死因 3：`.book` 没关文本选择

`.book` 上没有 `user-select:none` / `-webkit-touch-callout:none`，
系统会在长按中途接管成「文本选择 / 长按菜单」，同样发 `pointercancel`。已补上。

三条一起堵，不猜是哪一个——因为它们任何一条单独存在都会让长按失效。

#### 附带修掉的两个老问题

| 问题 | 说明 |
|---|---|
| `scroll` 监听从来没生效过 | 它挂在 `#grid` 上，但真正滚动的是父级 `.scroll`；`scroll` 不冒泡、`#grid` 也不在事件路径上。已删除（长按期间真滚动必然产生 `pointermove`，8px 容差会接住） |
| `longFired` 可能永久卡住 | 长按成功后如果 `click` 没来（`pointercancel` 场景），`longFired` 会一直是 `true`，下一次正常点击被自己吞掉，观感是「点了没反应」。已加 300ms 兜底复位 |

#### 测试

`tests/longpress.js` 现在 **20 项**（原 24 项，波纹相关的 4 条随功能一起删了）。
关键点：**把这三个文件换回补丁前的备份跑它，会红 3 条**——正好是「波纹已删除」的三条护栏，
说明护栏不是摆设；功能性的那 17 条在旧代码上依然是绿的，说明删改没有伤到长按本身。

> 顺带记两条断言纪律：
> 1. 断言界面文本读 `#app` 的 `textContent`，不要读 `body.textContent`——`body` 里含
>    `<script>` 源码，源码本身就带 `.editor-wrap` 之类的字符串，会造假阳性。
> 2. 写完断言要**拿旧代码跑一遍确认它会红**，否则无法区分「修好了」和「本来就没测到」。

### 为什么去掉 IIFE

原来整个 `app.js` 是一个 `(function(){ 'use strict'; ... })()`，所有视图共享闭包。
拆成 9 个文件后**必须去掉外壳**，让它们共享同一个全局作用域；如果每个文件各自包
一层 IIFE，视图之间互相看不见，切视图就白屏。

每个文件开头仍有一行 `'use strict';`（挂在全局，等于整段脚本严格模式）。
全局污染在这个 App 里可接受：没有第三方脚本，`HL` / `MD` / `Anim` 各挂各的命名空间，不冲突。

### 切分怎么做的

用 `/tmp/split_app.py`：词法扫描（跳过字符串 / 注释 / 正则 / 模板字符串）切出 49 条
顶层语句，再按首行前缀规则归到 9 个文件。两道校验：

1. **所有切片按序拼接后必须与原 IIFE 正文逐字符相等**（不是「去空白后相等」）——
   这条能抓住「切片之间的注释丢了 / 重复了」。
2. 9 个产物逐个过 `node --check`。

扫描器踩的两个坑（以后写类似工具会再遇到）：

- **注释不归位**：最初按「语句首尾」切片，语句之间夹的注释谁都不认领，拼接校验失败。
  改成切片首尾相连（`blocks`：从上一语句结束到本语句结束），注释就跟着后一条语句走。
- **`(` / `)` 不等于语句结束**：最初把 `)` 回到深度 0 当成语句结束，结果
  `function esc(s)` 的 `)` 就把语句切断了，83 条语句碎成大量 `{...}` 碎片。
  正确判定是：**只有 `}` 回到深度 0** 才可能是语句结束，且后面紧跟
  `catch` / `else` / `finally` / `while` 时要继续吞（`try{}catch(e){}`、
  `if{}else{}`、`do{}while()` 都是同一条语句）。

### 没动的部分

`bridge.js` / `highlight.js` / `md.js` / `anim.js` / `style.css` / 原生 Java 全部没动。
`app.js` 的**内容一字未改**——只是被搬到了 9 个文件里，语义等价由第 1 道校验保证。

### 拆分后的体积

| 指标 | 拆分前 | 拆分后 | 现在（含指示条、删掉泛光） |
|---|---|---|---|
| `app.js` | 70,195 B / 1790 行 | 拆成 9 个文件共 72,113 B（最大 363 行） | 同左 |
| 前端 js 总计（14 个文件） | 96,553 B | — | **101,300 B** |

## 二十、滑动指示条（NavIndicator，移植自 React 组件）

用户给了一段 React 的 `NavIndicator`（`@/content/effects/nav-indicator`）要求「尝试融合进信笺」。
落在**新建页的两个胶囊组**上（编码 3 个 / 格式 7 个），而不是底栏——原因见最后的「为什么不上底栏」。

### 文件

`app/navindicator.js`（204 行，离线无依赖，暴露 `window.NavIndicator`）：

| API | 说明 |
|---|---|
| `NavIndicator.attach(root, opts)` | 在一个容器里挂一条指示条，返回 `{sync, destroy}`；`opts` 可覆盖 `duration` / `thickness` / `glow` / `itemSelector` / `isActive` |
| `NavIndicator.syncAll()` | 把所有句柄重新量一遍 |
| `NavIndicator._handles` | 当前活着的句柄（测试用，也是查泄漏的窗口） |

CSS 只有两条：`.ni-root{position:relative}` 和 `.ni-bar`（`position:absolute`，几何走
`--ni-left/--ni-width/--ni-top`，颜色 `currentColor`，`pointer-events:none`，`opacity:0`，
拿到几何后加 `.on` 淡入）。

### 两种形态

| 形态 | 几何 | 过渡的属性 | 折行 |
|---|---|---|---|
| `line`（原组件形态） | 条目**下沿**一条细线（`top = offsetTop + offsetHeight`） | `left` / `width` | **直接落位不滑**（跨行的细线没有物理意义） |
| `block`（信笺加的） | 条目**整格**（`left/top/width/height` 全部取格子） | `left` / `top` / `width` / `height` | **照滑**（跨行移动一块是有意义的） |

新建页两个组都用 `block`。

### 为什么把胶囊改成「表格式」等宽格子

第一版是把指示条做成一条线，直接压在原来的胶囊下面。真机截图暴露两个问题：

1. 胶囊宽度由文字决定（`TXT .txt` / `Markdown` / `C` 长短差很多），线只能贴着单个胶囊走，
   看着像「挂歪了」；
2. 7 个格式胶囊在窄屏折行，线一到跨行就只能直接落位，反而没动画。

改成 `.chips.seg`（`display:grid` + `data-cols` 等分列 + 用 `inset` 阴影画格子线）之后：

- 每格同宽同高，列线行线连起来就是一张表；
- 指示条变成**整块填充**（`.ni-bar.block`，`background:var(--fg)`，`z-index:0` 压在文字下面），
  几何就是格子本身，精确到像素；
- 选中格的**文字反色**（`color:var(--bg)`，`transition:color .16s`），底色全交给那块填充，
  不会出现「两层填充」。文字颜色是渐变过去的，块滑到一半时对比度会短暂偏低，
  这是这种效果的固有代价（iOS 的分段控件也一样）。

`.chip` 的原有样式没动，设置页那些胶囊还是老样子——只有加了 `.seg` 的容器才走表格样式。

### 原组件的五条方法论，一条没改

1. **静止几何写在 CSS 变量上**，动画期间才写内联 `left/width`，`transitionend` 一来立刻清空内联值。
   这样过渡结束后 DOM 里不会留一个「过期的内联像素值」——窗口尺寸变了、字号变了，
   下一次落位仍然是干净的。
2. **只在「用户真的换了一项」时才滑**。首次量、选中项没变、几何没变、用户关了动效、
   条目折行（多行没有物理意义）——一律直接落位。
3. **滑动途中再次切换 → 重定向**（只改终点，不回到起点重来）。
4. **`ResizeObserver` + `window.resize` → 重新落位**。
5. **`transitionend` 只认 `left` / `width`**，`opacity` 之类的结束事件不收尾。

### 信笺侧改了四处

| 改了什么 | 为什么 |
|---|---|
| 减少动效的判断走 `Anim.enabled()` | App 里已经有自己的「设置 → 动效」开关，只看 `prefers-reduced-motion` 会漏掉它 |
| `glow` 默认 `false` | 用户明确不要泛光，虽然这是「静态发光」不是点击泛光，也不加 |
| 保留折行判断 | `.chips` 是 `flex-wrap`，7 个格式胶囊在窄屏会折成两行 |
| `destroy()` + 视图 `__cleanup` | 原组件靠 React 卸载，这里得手动摘 `resize` 监听和 `ResizeObserver`，否则每次进新建页漏一个 |

### 为什么不上底栏

`Nav.render()` 每次切视图都 `$app.innerHTML = ''` 重建整棵树，而底栏是**各个视图自己画的**
（`home` 和 `me` 各画一份，`create` 没有底栏）。所以「从主页滑到小家」时底栏节点是新建的，
指示条只能「首次量 → 直接落位」，永远滑不起来。
要让底栏滑，得把 `.tabbar` 提到 `$app` 外面常驻——那是一次 DOM 结构重构（底栏 3 项、
`.tabbar.hide`、返回键层级都挂在这上面），风险远大于收益，先不做。

### 测试

`tests/navindicator.js` **47 项**。jsdom 没有布局引擎（`offsetLeft/offsetWidth/offsetTop`
恒为 0），所以测试里给格子**打桩几何**，才测得到「测量 → 落位 / 滑动」这条真实分支。

覆盖：表格结构（grid 等分 / 无圆角 / 选中格不留两层填充）、静止时不留内联值、首次量不滑、
换格才滑且四属性一起过渡、`transitionend` 交还变量、途中切换重定向、`opacity` 事件不收尾、
点已选格不滑、**block 跨行滑**、**line 折行不滑**、关动效直接落位、离开视图句柄清空。

> 写这个测试时踩了个自己的坑：`line` 形态那组一开始忘了先把旧选中项的 `.on` 去掉，
> 结果两个格子同时「选中」，`activeItem()` 返回第一个，`changed` 为假 → 永远落位不滑。
> 报错信息是「换项时只动 left/width」失败。**不是代码错，是测试的装置搭错了。**

**反证**：把 `navindicator.js` 里 `settle()` 的三行「清空内联值」删掉，测试从 47/0 掉到 44/3
（「过渡结束：内联值交还给变量」「跨行结束后 top 也交还变量」「过渡结束会把内联值清空」）。

### 踩坑：切换完块就看不见了（已修）

用户反馈「切换的时候能看见，切换完就看不见了，亮色模式也一样」，两张截图分别是深色 / 浅色。

根因是一条五环的链，缺一环都不会复现：

| # | 环节 | 后果 |
|---|---|---|
| 1 | `settle()` 里 block 形态写 `bar.style.height = isBlock ? '' : ...` | 过渡结束清掉内联高度 |
| 2 | `.ni-bar` 的 `height` 写死 `2px`，四个几何里只有 `left / width / top` 走了 CSS 变量 | 清掉内联值后回落到 2px |
| 3 | 块形态没有别的地方给高度 | 选中块塌成一条细线 |
| 4 | `.chips.seg .chip.on{background:none;color:var(--bg)}` | 选中格文字被反色成背景色，底色**全靠指示条提供** |
| 5 | 块一没，字和底同色 | 深色白底白字、浅色黑底黑字，两个主题都「消失」 |

**修法**（两处，缺一不可）：
1. `style.css` 的 `.ni-bar` 改成 `height:var(--ni-height,2px)` —— 四个几何全部走变量，内联值清空后仍是正确高度；
2. `navindicator.js` 的 `settle()` 高度一律清空（`bar.style.height = ''`），不再按形态分叉。

顺手还修了末行留窟窿：`views/create.js` 加 `fillTail(box, cols)`，末行只剩 1 格时 `gridColumn: span 3` 横跨整行（格式组 7 格 = 3+3+1，否则最后一行右边空两格）。

**护栏**（`tests/navindicator.js` 47 → 49 项）：新增「过渡结束：块高度交还给 `--ni-height`（不退化成 2px 细线）」与「CSS：`.ni-bar` 的 height 走 `var(--ni-height)`，不是写死 2px」。
**反证**：把 `style.css` 的 `height:var(--ni-height,2px)` 改回 `height:2px`，49/0 → 47/2，红的正是这两条。

## 二十一、主题切换（ThemeReveal 移植：圆形揭示）

移植自 Operit 提供的 React 组件 `ThemeReveal`（`@/content/effects/theme-reveal/…`）。

### 位置：从设置里搬到了右上角

| 页面 | 位置 | 结构 |
|---|---|---|
| 主页 | 天气条**最右侧划出来的一块** | `.weather-bar > .w-info(可点，弹天气提示) + .theme-slot(竖线分隔) > .theme-btn` |
| 小家 | 标题行右端（原来那个占位的 `.t-gap` 换成按钮位） | `.topbar > .t-gap + .t-title + .theme-slot > .theme-btn` |
| 设置 | **已删掉「外观」整行** | 只剩「动效」 |

> 为什么搬：切主题是「随时想点」的操作，藏在「小家 → 设置」二级页里不合适；而且用户明确要求放在右上角、从天气条里划出来。天气条左边（`.w-info`）仍然整块可点，点它弹「天气模块将在第二阶段接入」，点右边按钮才会切主题，两者不打架。

### 原组件的六条方法论（原样保留）

1. 圆心 = 点击点（没有坐标时退到按钮中心），半径 = **盖住画布最远角的距离**（`hypot(max(x, w−x), max(y, h−y))`）；
2. `document.startViewTransition()` 把换主题前后做成两张快照，只对 `::view-transition-new(root)` 做 `clip-path: circle()` 动画；
3. `::view-transition-old/new(root){animation:none;mix-blend-mode:normal}` 必须写在 CSS 里 —— 不关掉默认交叉淡入，圆外也会跟着淡，看起来是整屏闪一下；
4. 过渡没起来（不支持 / 用户关了动效 / `ready` 被跳过）→ 直接换色 + 120ms 淡入兜底；
5. 过渡途中再点：**先记下「下一个目标」**，从目标翻回去，而不是从旧 DOM 翻；
6. `skipTransition()` 必须能收尾：视图卸载时不能留一个还在跑的过渡。

### 信笺侧改了四处

| 改了什么 | 为什么 |
|---|---|
| 换色统一走 `applyTheme()` | 本地存储 `xj:dark`、通知原生窗口底色这两件事都在它里面；原组件自己写 `dataset.theme` + `localStorage`，这里不能各写一套 |
| 主题的唯一真相是 `html.dark` 这个类 | 原组件读 `element.dataset.theme`，信笺一直用类，沿用它就不用改 `applyTheme` |
| 减少动效走 `Anim.enabled()` | App 里有自己的「设置 → 动效」开关，只看 `prefers-reduced-motion` 会漏掉它 |
| `attach()` 返回句柄 + `destroy()` | 视图是 `$app.innerHTML=''` 整棵重建，得手动摘监听 + `skipTransition()`；原组件靠 React 卸载 |

时间参数：时长 **300ms**（钳在 200–700，原来是 420ms，见下文「性能」）、缓动 `cubic-bezier(.2,.8,.2,1)`、兜底淡入 120ms / 从 0.6 起。

### 性能：为什么卡（用户反馈「有点卡顿」后的三处修复）

先量了环境：`ro.product.model PLC110` / Android 15 / WebView **153.0.8010.39** / 120Hz 屏。
所以不是「不支持 View Transitions」在走兜底，而是动画和关键帧本身太重。找到三个真凶：

| # | 问题 | 为什么卡 | 修法 |
|---|---|---|---|
| 1 | `applyTheme()` 里**同步**调 `Bridge.theme()` | 它正好落在 View Transition「旧快照已拍、新快照还没拍」那一帧里；原生 `applyTheme` 要 `setBackgroundDrawable` + `setStatusBarColor` + `setNavigationBarColor` + `web.setBackgroundColor`，一次 JNI 往返加一次整窗重排 | JS 侧把通知挪到 `requestAnimationFrame`（下一帧，快照已拍完），并合并连续点击只发最后一个值；原生侧加 `darkApplied` 记住已刷的底色，**没变就不再动窗口** |
| 2 | 换色的一瞬间，几十个元素各自开始 0.18~0.22s 的颜色过渡（`.book` / `.chip` / `.ni-bar` …） | 它们此刻被「新」快照盖在下面，谁也看不见，纯烧 GPU；而且新快照拍到的还是旧色，揭示结束后颜色才慢慢追上，观感是「卡一下又跳色」 | 过渡前后给 `html` 加/摘 `.vt-run`，CSS 里 `html.vt-run *{transition:none!important}` 全冻结；结束 / skip / 视图销毁都会摘掉 |
| 3 | 时长 420ms 的整屏 `clip-path` | `clip-path` 不是合成属性，伪元素上的圆形裁剪**每帧都要重新裁一遍整屏纹理**；120Hz 下 420ms = 50 帧全屏重裁 | 收到 **300ms**（36 帧）；`Anim` 关掉动效时直接不走过渡 |

**测试**：以上两条 JS 修复都有护栏 —— 「点击当帧没有同步去调 JNI（通知挪到下一帧）」和「揭示期间 html 挂上 vt-run」+「过渡收尾后摘掉 vt-run」+「CSS 里确有冻结规则」。
**反证**：把通知改回同步、把 `freeze(true)` 删掉，74/0 → **72/2**，红的正是这两条。

> 原生那一处（`darkApplied` 跳过重复刷窗）**没有自动测试**：Java 侧没有单测环境，只能靠装机后连点几次主题按钮时看是否还发涩。这是本次修复唯一的验证空白。

### 第二波：第一下特别卡、后面才起圆

用户二次反馈：「第一下卡顿，后面的有些延迟」。两个不同现象，两个根因：

| 现象 | 根因 | 修法 |

## 二十二、透明状态栏（edge-to-edge）

用户要求：「把状态栏调整为透明」。

### 做法

| 侧 | 改动 |
|---|---|
| 原生 | `onCreate` 里 `addFlags(FLAG_DRAWS_SYSTEM_BAR_BACKGROUNDS)` + `setDecorFitsSystemWindows(false)`（API<30 用 `SYSTEM_UI_FLAG_LAYOUT_FULLSCREEN \| LAYOUT_STABLE`）→ 系统不再替我们留状态栏那一条；`setStatusBarColor(TRANSPARENT)`（`applyTheme` 里也是透明，不再刷底色） |
| 原生 | 新增 `insetsJson()` → `{"top":96,"bottom":48}`，经 `XinJianBridge.insets()` 暴露，同步返回 |
| Web | `--safe-t:env(safe-area-inset-top,0px)`，`.view{padding-top:var(--safe-t)}` 让出顶部；`boot.js` 的 `applyInsets()` 优先用原生报的像素写内联变量（`env()` 只是浏览器演示模式的兜底）；底部导航栏仍刷底色，占位走 `--safe-b` |
| Web | `.weather-bar` 的高度算式里加上 `--safe-t`，否则首页第一屏会高出一点点 |

### 为什么不用 `env()` 了事

`env(safe-area-inset-*)` 要 WebView 拿到窗口 insets 才有值，不同 ROM/WebView 版本给不给说不准；给不到就是 0，那顶栏直接被状态栏压住。所以真实像素由原生报，CSS 变量只做兜底 —— 两条路都留着。

### 状态栏区域露出的是什么

`.view` 是 `position:fixed; inset:0` 且背景是 `--bg`，状态栏那一条下面就是它，所以看上去就是「页面底色透上来」。切换主题时 `.view` 的背景、`html` 的内联底色、原生窗口底色三者一起变，不会出现一条突兀的色带。

### 测试

`tests/theme.js` 新增 7 项：`--safe-t` / `--safe-b` 按原生上报的像素写好、CSS 里 `--safe-t` 有 `env()` 兜底、`.view` 确实用了 `padding-top:var(--safe-t)`，以及四条源码级护栏（原生 `setStatusBarColor(Color.TRANSPARENT)` / `setDecorFitsSystemWindows(false)` / `insetsJson()` / 桥的 `insets()` / `bridge.js` 的 `insets: function ()`）。

**反证**：把 `boot.js` 里的 `applyInsets()` 注释掉，89/0 → **85/4**，红的是前两条。

> **没测到的**：insets 的真实像素、状态栏是不是真的「透」、内容有没有被状态栏压住 —— 这些只有真机能看到。（2026-11-25 用户确认「主题问题 ok 了」，本轮状态栏改动一并未再被提出问题，按通过处理。）另外 `applyInsets()` 在启动时、启动后 300ms 和每次 `resize` 都会重取（冷启动那会儿窗口 insets 可能还是 0），但**分屏/折叠屏的 insets 变化没有专门测**。

## 二十三、动效提速（2026-11-25）

用户反馈两条：「书架长按后的动效……慢半拍的感觉」，以及「振动响应时间应当最长为 0.5s」。

> 关于「振动」：全工程搜过 `vibrat / haptic / navigator.vibrate / 振动 / 触感`，**信笺从来没有写过振动**，
> Manifest 里也没有 `VIBRATE` 权限。所以这条按「长按要按多久才有反应」来落地 —— 那是全工程唯一一处
> 「按下后要等一段才响应」的地方，也符合「慢半拍」的体感。若之后真要加触感反馈，那是新功能而不是调参。

### 改了什么

| 参数 | 原值 | 现值 | 位置 |
|---|---|---|---|
| 错峰步长（相邻两格起跳间隔） | 40ms | **24ms** | `anim.js` 的 `stagger()` 默认值 |
| 单格升起时长 | 0.24s | **0.16s** | `style.css` 的 `.stg-run` |
| 升起位移 | 0.625rem | **0.4rem** | `style.css` 的 `@keyframes xjStg` |
| 动画后摘类的兜底延时 | 320ms + maxDelay | **220ms + maxDelay** | `anim.js` |

按 10 格算，整屏收完从 **40×9+240 = 600ms** 降到 **24×9+160 = 376ms**，少了约 37%。

### 踩坑：同一个数值写在两处

第一次只改了 `anim.js` 的默认步长（40 → 24），`tests/anim.js` 立刻红在「错峰步长 24ms」，
因为 `views/shelf.js` 的 `staggerCells()` 里是**显式传参**：

```js
Anim.stagger(list, { step: 40 });   // 覆盖了 anim.js 的默认值
```

也就是说「默认值」从来没被书架用过。改法是把 `shelf.js` 的显式传参**删掉**，让步长只在
`anim.js` 里存在一处。这样以后再调只改一个地方，也不会出现「改了没效果」。

### 长按响应时间（产品约束：最长 0.5s）

| 参数 | 原值 | 现值 |
|---|---|---|
| 长按触发阈值 | 600ms（`shelf.js` 里写死的数字字面量） | **450ms**（具名常量 `PRESS_MS`） |

改法不只是换数字：
- 数字提成 `var PRESS_MS = 450;`，计时器写 `}, PRESS_MS);`，注释里写明「产品约束最长 0.5s」；
- 测试加了三道护栏：常量存在、**值 ≤ 500**、计时器用的是常量而不是字面量；
- 加了一条**行为**护栏：按下 380ms 时不许进多选（防误触）、530ms 时必须已经进（响应 ≤ 0.5s）。

为什么取 450 而不是正好 500：留 50ms 余量吸收真机 touch slop 与主线程抖动，
这样「最长为 0.5s」在体感上仍然成立。要更保守可以用 500，加一行都不用改测试。

### 测试

`tests/anim.js` 的步长断言 40 → 24；`tests/longpress.js` 从 20 项加到 **25 项**（新增长按阈值三条源码护栏
+ 380ms/530ms 两条行为断言）。全套 **618 项 / 18 文件全绿**。

**反证**：把 `PRESS_MS` 改回 `600`，`longpress` 25/0 → **23/2**，红的正是「530ms 内已经进入多选（响应不超过 0.5s）」
和「长按阈值不超过 0.5s（当前 600ms）」这两条。改回 450 立刻恢复 25/0。

### 踩坑：提速把两条老测试的「假等待」弄红了

`tests/anim.js` 原来是 `down()` 之后写死 `await wait(750)` 再断言「动画类已挂上」。
以前长按 600ms 触发、动画 .24s + 错峰 → 750ms 时动画类还在，正好抓得到。
这次长按 450ms 触发、动画收到 .16s → 类在 **~718ms** 就被摘掉了，750ms 时已经没了，
于是这条断言先红。**红的是测试的假设，不是产品代码**：动画确实跑过、也确实收干净了。

改法是把固定等待换成轮询 `until(fn)`：一看到「已选」出现就立刻查中间态，
不管以后阈值和时长怎么调都不会再因为窗口错位而假红。

**没测到的**：0.16s / 24ms / 450ms 这组数值「手感够不够快」只有真机能判断 —— jsdom 不算动画时间，
测试只能保证「数值确实传到了 DOM 上」「动画跑完 DOM 回到静止态」「长按在 0.5s 内响应」。

## 二十五、卡片光斑（SpotlightCard 移植）

用户要：「把这个代码融合进我们每一张卡片里」—— 主页四张卡片、书架所有书籍（并给以后新增的默认附加）、
鸽屋列表每个聊天行，其中聊天行**仅覆盖右半边，不要让人看出明显分界**。

原组件是 React + Motion 的 `SpotlightCard`：跟随指针的径向光斑 + 3D 倾斜 + 悬停放大 + 1px 描边高光。

### 挂在哪（一张表看完）

| 位置 | 元素 | 形态 |
|---|---|---|
| 主页四个入口 | `.entry` | 整卡光斑 + 描边高光 |
| 书架每一本 | `.book` | 整卡光斑 + 描边高光 |
| 鸽屋每一行 | `.pg-item` | **仅右半边**，左缘渐变化开，无描边高光 |

选择器集中在 `app/spotlight.js` 顶部两行（`CARDS` / `HALF`），加新类型只改这一行：

```js
var CARDS = '.entry, .book, .pg-item';
var HALF = '.pg-item';
```

### 三件事决定了这个移植的做法

**1）用事件委托，视图里一行挂载代码都没有。**
监听挂在 `document` 上，`pointerdown/move/up/cancel` 时用 `closest(CARDS)` 找卡片。
所以「以后新增的书籍默认附加」不用做任何事 —— 视图每次重建 DOM、新书渲染出来，
它在第一次被按下时自动挂上 `.spot`。测试里有一条护栏：`views/*.js` 里不许出现 `Spotlight` 字样。

**2）绝不往卡片里插 DOM 节点。**
书架长按曾被这个坑搞挂过：`pointerdown` 时往卡片里插节点，部分 WebView 认为手势期间 DOM 有变动，
直接派发 `pointercancel`，把长按计时器一起掐掉（见第十八节「踩坑」）。
所以光斑用卡片自己的伪元素画：

| 伪元素 | 画什么 |
|---|---|
| `::after` | 光斑本体（`radial-gradient`） |
| `::before` | 1px 描边高光（两条蒙版做 xor，只留一圈） |

两个伪元素都是 `z-index:-1`，而卡片自己 `position:relative;z-index:0` 建了层叠上下文 ——
于是光斑压在**卡片背景之上、正文之下**，文字不会被一层灰糊住。

**3）坐标走 CSS 变量 + rAF 合并。**
`pointermove` 只记最新坐标，一帧只写一次 `--spot-x/--spot-y`；`requestAnimationFrame` 合并连发事件。
没有 `will-change`（不给每张卡片单独开合成层，书架几十本时那会直接吃掉显存）。

### 鸽屋「只画右半边」是怎么做到的

伪元素盒子改成右半区，再减半宽：

```css
.spot-half::after{
  left:auto;right:0;width:50%;
  -webkit-mask-image:linear-gradient(to right,transparent 0,#000 45%);
  mask-image:linear-gradient(to right,transparent 0,#000 45%);
}
.spot-half::before{display:none;}   /* 描边高光会在中线画出半圈硬边 */
```

```js
if (activeEl.classList.contains('spot-half')) x -= rect.width / 2;
```

两个细节：
- **坐标要减半宽**，否则光斑会整体往右偏半个卡片；
- 手指在中线**左边**时算出来是负值，正好落在右半盒之外 —— 于是左半边天然不会漏光，
  不需要额外判断。左缘那条硬边靠 `0→45%` 的渐变蒙版化开，所以看不出「半个卡片」。
- 描边高光在鸽屋行上关掉：一圈 1px 亮边会在中线处出现半圈断口，反而更显眼。

### 与原组件的差异（都是有意的）

| 原组件 | 这里 | 为什么 |
|---|---|---|
| `rotateX/rotateY` 倾斜、`scale` 悬停放大 | **没有移植** | 原组件自己就写着 `if (pointerType !== "touch")` 才做。手机没有 hover，触屏上这两条本来就不触发；移植过来是死代码，还会和手指滚动抢 `transform` |
| Motion 的 `useSpring` 弹簧缓动 | CSS `0.12s` 淡入淡出 + 直接跟手 | 一次手势里弹簧会把延迟叠上去（前面刚把「慢半拍」修掉，不该再加回来） |
| 关动效时保留一个静止的居中光斑 | 完全不画 | 信笺的既有约定是「关掉动效就彻底不动」，不留中间态 |

### 测试

新增 `tests/spotlight.js` **41 项**，全套升到 **659 项 / 19 文件全绿**。覆盖：

- 三类卡片都真的存在并会亮（主页 4 张 / 书架 / 鸽屋行），坐标按视口→卡片正确换算；
- **按下前后子节点数不变**（把「不插节点」这条老雷守死）；
- 新增一本书之后，新卡片不用改代码就有光斑；
- 鸽屋行：挂 `.spot-half`、右半区坐标减半宽、中线左边为负值、左缘蒙版与描边关闭；
- 连发 `pointermove` 只渲染最后一帧；抬手 `--spot-o` 归 0、活动卡片清空；
- 关动效后不挂 `.spot`、不激活；
- 源码护栏：不出现 `createElement/insertBefore/appendChild/innerHTML`、有 rAF、坐标走变量；
- CSS 护栏：`.spot::after` 是径向渐变、半区 `width:50%`+`right:0`、蒙版存在、`z-index:-1`+卡片建层叠上下文；

## 二十六、去「网页感」（长按不弹菜单 / 暗色米黄白）

用户提：「可以去掉网页感吗？就是那种长按选取文字，更贴近一个真实 APK 的感觉」。

先分清一件事：网页感来自**三个不同的来源**，各管各的 —— CSS、WebView 的 setter、以及主题色。

### 1）长按选字：用 CSS 限制范围，**不**关 WebView 的长按

产品决定：**Markdown 阅读态要保留长按选中复制**。所以不能调 `setLongClickable(false)` ——
那会把阅读态的复制一起干掉，而且工具条是系统画的，一旦关掉就没有「只要一半」的可能。

改用 `user-select` 划定范围：

```css
*{-webkit-user-select:none;user-select:none;-webkit-touch-callout:none;}
input,textarea,select,[contenteditable="true"],[contenteditable="true"] *,
.md-body,.md-body *,.msg .bubble,.msg .bubble *{
  -webkit-user-select:text;user-select:text;-webkit-touch-callout:default;
}
```

效果：**长按只在阅读态 / 聊天气泡 / 输入框里有反应**，别处长按什么都不会发生，
也就不会冒出系统的「复制 / 全选」工具条。

> **坑（很重要）**：`user-select` 本来是继承属性，但 `*{user-select:none}` 会把**每一个**元素
> 都显式设成 `none`，继承链就断了。所以白名单必须连后代一起写（`.md-body *`），
> 否则 `.md-body` 自己能选，里面的 `<p>` / `<code>` 仍然选不了 ——
> 只测 `.md-body` 自己是会假通过的（测试里专门有这条）。

### 2）其余浏览器行为，原生侧关

| 网页感 | 修法 | 位置 |
|---|---|---|
| 滚到头的灰蓝辉光 | `setOverScrollMode(OVER_SCROLL_NEVER)` + CSS `overscroll-behavior:none` | `MainActivity` / `style.css` |
| 滚动条 | `setVerticalScrollBarEnabled(false)` `setHorizontalScrollBarEnabled(false)` + `::-webkit-scrollbar{width:0;height:0}` | 同上 |
| 长按那一下震动 | `setHapticFeedbackEnabled(false)` | `MainActivity` |
| 字忽大忽小（像网页） | `setTextZoom(100)` + `text-size-adjust:100%` | 同上 |
| 缩放控件 | `setSupportZoom(false)` `setBuiltInZoomControls(false)` `setDisplayZoomControls(false)` | 同上 |
| 点一下灰块闪 | `-webkit-tap-highlight-color:transparent` | 本来就有 |
| 外接键盘的焦点框 | `:focus{outline:none}` | `style.css` |

**故意没做**的：`setLongClickable(false)`（见上）、以及输入框里的系统选择手柄外观（Chromium 内建，改不了）。

### 3）暗色下白色不是纯白

用户要求：「暗色模式下，白色不再是纯白，而是米黄白，这样护眼，不然黑白对冲伤眼睛」。

```css
html.dark, body.dark{
  --bg:#1E1E1E;
  --fg:#F1E9D8;          /* 原来是 #FFFFFF */
  --fg-rgb:241,233,216;  /* 必须同步，否则描边/光斑还是纯白 */
}
```

- 纯白压在 `#1E1E1E` 上对比约 **15:1**，是极端值；米黄白降到 **12:1** 左右，仍然是 AAA 级；
- `--fg-rgb` 必须一起改 —— 分隔线、卡片描边、卡片光斑、各种 `rgba(var(--fg-rgb),x)`
  全靠它，漏改就会出现「字是暖的、线是冷的」；
- 亮色主题一个字节没动（仍是白底深字）。

**没动的地方**：`style.css` 里三处字面量 `#fff`（toast / 弹层按钮的图标和文字），
它们压在自己的深灰底 `#4A4A4C` 上、两个主题下都一样，属于「深色浮层上的白图标」，
不是主题文字色，所以保持纯白。

### 测试

新增 `tests/webview.js` **28 项**（全套升到 **687 项 / 20 文件全绿**）：

- 用 `getComputedStyle` 验真实计算值，不是只 grep 源码：卡片 / 外壳 / 顶栏是 `none`，
  阅读态**及其后代**、`textarea`、`input`、聊天气泡是 `text`；
- 暗色下 body 的 `color` 解析出来必须是 `rgb(241, 233, 216)`，且不等于纯白；
  底色仍是 `rgb(30, 30, 30)`；用 `--fg-rgb` 画的 `.line` 也必须是暖的；
- 原生源码七条：overscroll / 两条滚动条 / 震动 / textZoom / 缩放支持，
  外加**反向一条**：确认没有 `setLongClickable(false)`。

**反证**：把白名单的 `.md-body *` 去掉（只留 `.md-body`）+ 暗色改回 `#FFFFFF`，
28/0 → **22/6**，红的正是「阅读态的后代也可选中」和五条米黄白相关断言；还原后立刻回 28/0。

### 踩坑：护栏被自己的注释绊倒

「确认没调 `setLongClickable(false)`」这条断言第一次是**红的**，因为我在 `MainActivity`
的注释里正写着「**故意没有**调 `setLongClickable(false)`」这句话 —— 正则扫到了注释里的字面量。
修法是断言前先把 `/* */` 和 `//` 注释剥掉再匹配。（这类假红很值得记：源码级护栏要区分
「代码里有没有」和「注释里提没提」。）

### 没测到的

- **真机手感**：光说 CSS 就是 `user-select:none`，但「长按到底还会不会震一下、会不会闪一个选择手柄」
  只有真机能确认（尤其有些 ROM 自带的 `WebView` 长按行为不完全等于 Chromium 默认）；
- **米黄白好不好看**：`#F1E9D8` 是我按「12:1、带一点暖调」挑的，偏黄还是偏冷需要你眼睛判断，
  改一个变量就能调；
- 系统字体缩放：`setTextZoom(100)` 会让应用忽略系统字体大小设置（这是「不像网页」的代价），
  如果你希望跟随系统字体，这条要撤掉。

### 2）「所有动效都没了」的最终结论

上一轮六个假设全部证伪：

| # | 假设 | 证据 | 结论 |
|---|---|---|---|
| 1 | CSS 注释 / 括号被我插坏了 | 注释 61/61 配平，大括号净深度 0 | 否 |
| 2 | 动效规则被丢弃 | `.stg-run`、`@keyframes xjStg`、`.spot::after`、10 条 `transition` 全在 | 否 |
| 3 | 用户总开关关了 | leveldb 里 `xj:anim` = `on` | 否 |
| 4 | 系统关了动画 | 三个 `animator_duration_scale` 都是 `1.0` | 否 |

埋在 `boot.js` 里的诊断（装于 `02:06:39`）最终写盘，内容：

```json
{"mq":false,"animOn":true,"rules":230,"hasStg":true,"hasMedia":true,
 "vt":false,"animAsset":"ok","probeAnim":"xjStg/0.16s","transMs":-1}
```

| 字段 | 含义 | 读出的结论 |
|---|---|---|
| `mq` | `prefers-reduced-motion` 是否匹配 reduce | **false** —— 假设 5 证伪 |
| `animOn` | `Anim.enabled()` 返回值 | **true** —— 假设 6 证伪 |
| `rules` | 样式表规则数 | 230，加载正常 |
| `probeAnim` | `.stg-run` 探针算出的 `animationName/animationDuration` | **`xjStg/0.16s`** —— 动画在运行时真实生效，且 `0.16s` 正是提速后的新值 |
| `transMs` | 一次 100ms 过渡是否收到 `transitionend` | `-1`（没跑）。**但这是探针自身的问题**：元素被放在 `left:-999px` 且立即改 `opacity`，WebView 可能把这类离屏元素排出合成层，`transitionend` 就不派发。**不能当成「过渡坏了」的证据** |

**结论**：后端在真机上的动效计算值是对的，六个假设全部证伪，用户随后确认「动效我看了，恢复了」。
根因**始终没有确证**（最可能是上一轮装机时 WebView 用的是旧的缓存快照）。
这一条按「已解决但原因未定」记录，不再追查；诊断代码已删。

### 4）v3 签名怎么弄

只有一行：`apksigner` 本来就支持，加一个开关。

```bash
apksigner sign --ks "$KS" --ks-key-alias "$ALIAS" \
          --ks-pass "pass:$STOREPASS" --key-pass "pass:$STOREPASS" \
          --v1-signing-enabled true --v2-signing-enabled true --v3-signing-enabled true \
          --out "信笺.apk" "aligned.apk"
```

三个方案各自管一段系统版本，不是三选一，是**都要开**：

| 方案 | 生效范围 | 作用 |
|---|---|---|
| v1（JAR） | Android 6 及以下 | 老系统只认这个 |
| v2（APK Signature Scheme v2） | Android 7+ | 整包签名，防篡改 |
| v3 | Android 9+ | 支持**密钥轮换**：以后换密钥也能给老用户平滑升级 |

同时把 `apksigner verify` 改成 `--verbose`，让每次打包都把三个方案的通过情况打出来：

```
Verified using v1 scheme (JAR signing): true
Verified using v2 scheme (APK Signature Scheme v2): true
Verified using v3 scheme (APK Signature Scheme v3): true
```

`v4` 是 `false`，正常 —— v4 是给 `adb install --incremental` 用的独立 `.idsig` 文件，
发行 APK 不需要。

## 二十八、鸽屋 · 局域网通信（0.3，2026-11-25）

用户要求先做局域网（蓝牙后做），并拍定五条：

1. 身份标识用**设备指纹**，产品名「**鸽子窝**」
2. 好友关系**必须点击添加**才能建立会话
3. 离线消息**先不做**
4. 图片**先不发**
5. 有第二台设备，蓝牙后续无阻碍

### 1）为什么必须在原生做

WebView 里的 JS 只能发 HTTP / WebSocket：

| 能力 | JS（WebView） | 原生 Java |
|---|---|---|
| 发 UDP 广播做「附近发现」 | ❌ 不可能 | ✅ |
| 开 TCP 服务端等别人连 | ❌ 不可能 | ✅ |
| 蓝牙 RFCOMM | ❌ 不可能 | ✅ |

所以通信全在 Java，前端只做三件事：发指令、收事件、画界面。

### 2）两个端口

| 端口 | 协议 | 作用 |
|---|---|---|
| **UDP 45789** | 广播 | 每 3s 向 `255.255.255.255:45789` 播一条 announce，收到就记下对方 IP |
| **TCP 45790** | 长连接 | 谁先发消息谁去连，连上后双向收发，换行分隔的 JSON |

**必须持有 `MulticastLock`**：WiFi 芯片默认过滤广播/组播包，不 acquire 这个锁，
一条 announce 都收不到（表现为「附近永远没人」，且不报错）。所以新增
`CHANGE_WIFI_MULTICAST_STATE` 权限，运行时 `WifiManager.createMulticastLock()`。

### 3）身份：鸽子窝号

`Settings.Secure.ANDROID_ID` 取前 12 位十六进制，前缀 `xj-`。
这个值**不需要任何权限**，同一台设备 + 同一个签名键下永久稳定，换机就换。

原来的 `Profile.sid` 是 `'xj-' + 随机 4 位数`（9000 种），局域网里撞号概率不能接受，
所以局域网身份不用它。

### 4）协议

```
{"v":1,"t":"ann",  "id","nick","tcp"}   UDP 广播
{"v":1,"t":"hello","id","nick","tcp"}   TCP 建链握手（双向各发一次）
{"v":1,"t":"msg",  "mid","from","to","text","ts"}
{"v":1,"t":"ack",  "mid"}
```

推给 Web 的事件（`window.__xjNet(json)`）：

```
{"t":"peer","id","nick","online":true}   对方上线 / 昵称变了
{"t":"offline","id"}                     超过 11s 没广播，判掉线
{"t":"msg","id","mid","text","ts"}
{"t":"ack","mid"}
{"t":"state","on":bool}
```

### 5）好友 = 手动添加

UDP 广播会看见同一个 WiFi 下**所有**装了信笺的设备。产品决定：**发现 ≠ 加好友**。

- 广播只用来生成「附近的人」列表（`+` → 添加朋友）
- 用户点某一台，才 `Pigeon.create(昵称, 鸽子窝号)` 建会话，并把 `peer` 字段绑上该号
- 已加过的设备不再出现在「附近的人」里；重复添加直接回到已有会话
- 收到 `msg` 时，`from` 不是本会话绑定的 `peer` → **直接丢弃**，不建会话
  （所以陌生人无法靠发消息在你这里凭空长出一个会话）

### 6）送达状态

`netSend` 返回 `ok` **只代表写进了 TCP socket**，不代表对方收到。真正的送达看 `ack`：

| 状态 | 界面文案 |
|---|---|
| `sending` | 发送中… |
| `ok`（收到 ack） | 不显示 |
| `fail`（socket 就写不进去） | 未送达 |
| 无 `st`（老数据 / NPC / 媒体） | 本机 · 未送达 |

第一版**不做离线补发**：对方不在线，消息就停在「未送达」。

### 7）两个跑在原生里的坑

**坑 1：同一条消息可能走两条连接到达。** 双方各自 `connect` 一次，会形成两条 socket。
两条都可能把同一条 `msg` 送过来，所以前端按 `mid` 去重（`Pigeon.hasMid`）。

**坑 2：socket 断了要能自愈。** `readLoop` 结束时会 `forget(socket)`，把还指着它的
peer 的发送通道清空；下次发消息发现 `out == null` 就重连。不这么做，对方重启应用后
这边会一直往死 socket 写，消息全部石沉大海还不报错。

### 8）UI 变化

| 位置 | 变化 |
|---|---|
| 鸽屋列表 | 每个绑了设备的会话，名字后面多一个小圆点：绿=在线，灰=不在线 |
| 会话页底部提示 | 显示 `鸽子窝 xj-xxxx · 在线 / 对方不在线` |
| `+` → 添加朋友 | 不再是输入框，改成「附近的人」列表（昵称 + 鸽子窝号） |
| 演示模式（浏览器） | 点添加朋友提示「演示模式：没有局域网」，**不会凭空建会话** |

## 二十九、好友验证 + 会话设置 + 通知（0.4，2026-11-25）

### 1）用户报的 bug

> 「a 加了 b，发给 b 消息，实际上 b 不会第一时间收到，必须回加 a 才能正式通话。」

期望：a→b 是**验证消息**，b 在列表收到并收到系统通知，通知点了直接跳鸽屋；
b 回复才表示同意，之后才正常聊天。会话页右上角还要一个三条杠进二级页。

### 2）根因（两层，都有行号为证）

第一层，`app/views/chat.js` 里收消息时写的是：

```js
if (!pid || ev.id !== pid) return;   // pid = 本会话绑定的鸽子窝号
```

b 端根本没有会话，`pid` 为空，第一个条件就 return，陌生人消息被直接丢掉。
这一句是 0.3 按「好友必须手动点添加」故意写的，没留验证通道。

第二层更硬：`Net.start` 只在 `views/chat.js` 的鸽屋列表和会话页两处调用。
b 不在那两页时 UDP/TCP 监听**根本没启动**，消息连 socket 都进不来。
用户「回加 a 就能通」正好同时解掉两层：回加建了会话（绑 peer）+ 人正在鸽屋页（监听着）。

顺带发现：清单里 `POST_NOTIFICATIONS` 计数为 0，原生侧没有任何 Notification 代码，
通知是从零开始做的。

### 3）三个产品决策（用户拍定）

| 问题 | 选择 |
|---|---|
| 后台常驻做到什么程度 | **A**：进 App 就开监听，退后台但进程还活着就能收；做成开关，默认开 |
| 回复即同意是哪种 | **A**：b 直接打一行字发出去就算同意，这行字即第一条消息 |
| 免打扰压到什么程度 | **B**：通知和红点一起压 |

追加要求：**删除好友也要做**。

### 4）数据层（`app/data.js`）

- `db.requests` 独立字段（不塞进 `sessions`），键是对方鸽子窝号，
  值 `{peer, nick, text, t, n, unread}`。老库加载时补这个字段。
- `Pigeon.title(s)`：有备注用备注，否则用昵称。列表和顶栏都走它。
- `Pigeon.setNote`（截 20 字）、`setMute`。
- `Pigeon.requests()` 按时间倒序、`reqCount()` 数未读、`getRequest`、
  `addRequest`（同 peer 去重，`n` 累加，`unread` 累加）、`markReqRead`、`dropRequest`。
- `Pigeon.findByMid(mid)`：回执只带 mid，不知道属于哪个会话，必须全局扫。
- 新增 `PgSet`：`xj:pigeon:set`，字段 `resident`，**默认 true**。

### 5）全局收件（本轮的核心修复）

新增 `PigeonInbox`（也在 data.js），启动时挂到 `Net` 上，**不管当前在哪一页都收**：

1. 好友发来的 → 落盘进会话；没开着这个会话且没免打扰 → 发通知
2. 陌生人发来的 → `addRequest`，发「验证消息」通知，**不自动建会话**
3. `ack` 回执 → `findByMid` 全局找，标 `ok`

为此把 `net.js` 从「单监听者」改成**多监听者**（`sinks` 数组）：
全局收件和当前页面的重绘是两个订阅者，只留一个槽就会互相顶掉。
`setSink` 保留但语义变成「追加」，`clearSink(fn)` 只摘自己。

### 6）协议：`msg` 帧补 `nick`

`{"v":1,"t":"msg","mid","from","nick","to","text","ts"}`

b 第一次收到陌生人的消息时本地没有任何记录，只靠 id 无法显示「谁在请求加你」。
推给 JS 的 `msg` 事件也带 `nick`；若对端是旧版本（不带 nick），
退回 `peers` 表里查，查不到就空着。

### 7）视图

**鸽屋列表**：验证请求置顶，虚线头像 + `新`/未读数徽标 + 「请求加你为好友：<正文>」；
会话名走 `Pigeon.title()`，免打扰的会话在名字后加一个小字「免打扰」。
列表会在 `msg`/`ack` 事件后重画（最后一条消息要跟着变）。

**会话页**支持两种进法：

- `{peer}` 从验证条进来 → 待验证态：只显示对方那句 + 「回复一句话就表示同意，你的回复会直接发出去」
  - 此时三条杠点了只提示「先回一句话才是好友」
  - 发媒体会提示「成了好友再发」

## 三十、邀请态：对方回复前只能发一条（0.4.1，2026-11-25）

### 1）用户报的 bug

> 「a 发给 b 验证消息后，a 不应该可以继续发送，应当无法发送消息直至 b 回复。」

上一轮只做了 b 侧「陌生人消息转验证请求」，**a 侧没有任何等待状态**：
a 加完 b 就是一个普通会话，想发多少发多少。这说明上一轮只实现了一半 ——
b 那边看到的是一条“验证”，a 这边却按正式聊天在发。

### 2）设计：用「有没有一条发出去的邀请」当锁

数据层给会话加一个 `invite` 标记，语义是「我主动加的，还在等对方回第一句」。

| 时机 | 动作 |
|---|---|
| a 从「附近的人」添加 | `Pigeon.create(name, peer, true)` → `invite = true` |
| a 发第一条 | 照常发送；一旦有一条 `st !== 'fail'` 的 outgoing 消息，就锁住 |
| a 想发第二条 | `Pigeon.canSend(sid)` 返回 `{ok:false, why:'wait'}`，拦住 |
| b 回第一句 | `Pigeon.add(..., 'in', ...)` 里顺手把 `invite` 置空 → 自动解锁 |

`canSend` 放在数据层而不是视图，是为了同时挡住三条路：点击发送、回车、媒体面板。

### 3）一个必须处理好的边角：发送失败要能重试

如果锁的条件写成「已经有一条 outgoing 消息」，就会死锁：
对方不在线 → 第一条标 `fail` → 但它也算“发过了” → a 永远发不出去，
而 b 永远不知道有人加他。

所以判断条件是 **`m.dir === 'out' && m.st !== 'fail'`** ——
未送达的不算数，a 可以重发，直到真的送进 socket 为止。
视图里 `fail` 状态本来就会显示「未送达」，语义也自洽。

### 4）界面

| 位置 | 表现 |
|---|---|
| 底部提示条 | 「验证消息已发出，等对方回复后才能继续聊。」 |

| 发送按钮 | 加 `.off` 压到 0.35 透明度（不 disable，点了给 toast 说明原因） |
| 鸽屋列表 | 会话名后面挂一个小字「待验证」 |

三处视觉 + 两处拦截（`send()` / `pushMsg()`），少任何一处都能被绕过。

### 5）边界：对方先加我，我再去加他

如果 a 这边还挂着 b 的验证请求（`Pigeon.getRequest(pid)` 有值），
a 从附近的人点添加时**不进入 invite 态**，而是把 b 那句搬进历史、删掉请求。
理由是双方都已经表态，等价于互相同意，再锁就没道理了。

## 三十一、输入法焦点：发完消息键盘不再收起（0.4.2，2026-11-25）

### 1）用户报的问题

> 「每次发完一句消息输入法就被收起来了，这属于体验上的问题」

### 2）根因

修复前 `views/chat.js` 里**完全没有**任何 `focus` / `blur` / `mousedown` 处理。点发送按钮时走浏览器默认行为：焦点从 `#chatIpt` 移到 `<button>` → input 失焦 → Android WebView 立刻收起软键盘 → 表现是「每发一句都得重新点一下输入框」。

### 3）三层修复

| 层 | 位置 | 做法 | 为什么必须这样 |
|---|---|---|---|
| 1 | `sendBtn` 上 `mousedown` | `e.preventDefault()` | 阻止焦点从 input 转到 button。**只能拦 mousedown**：在 touchstart 上 preventDefault 会把 click 一起吞掉，消息直接发不出去 |
| 2 | `send()` 外层包装 | 发完 `setTimeout(() => ipt.focus(), 0)` | 回车发送、部分机型 IME 提交后会自己失焦，仍需兜底 |
| 3 | input 的 `keydown` | 先 `e.preventDefault()` 再 `send()` | Android 输入法把回车当成「完成」，提交后自动收键盘 |

`doSend()` 里有 6 处提前 return，所以回焦写成包装层，不在每个出口写一遍。

### 4）测试抓出来的真实 bug（这一节是重点）

给「离开兜底」补测试时，断言红了。插桩 `document.body.contains` 后拿到铁证：

```
CLICK 前 connected=true
BODY.CONTAINS ret=true connected=true tag=INPUT   ← 只在 click 期间求值了一次
CLICK 后 connected=true
FOCUS CALLED connected=false                      ← 执行时节点已经脱离文档
```

**原来的写法把 `contains` 判断放在了 `setTimeout` 外面。** 判断发生在「注册那一刻」（输入框还在页面上 → 放行），而 `focus` 发生在「下一个宏任务」。用户点完发送立刻按返回，视图在这两者之间被拆掉，于是对着游离节点执行 `focus()`——Android WebView 上的表现是**「已经退出会话了，键盘自己跳出来」**。

修法：把判断挪进 `setTimeout` 内部。

```js
function send() {
  doSend();
  setTimeout(function () {
    if (!document.body.contains(ipt)) return;   /* 视图已销毁，别去碰它 */
    try { ipt.focus(); } catch (e) { }
  }, 0);
}
```

`jsdom` 的 `click()` **既不派发 mousedown，也不会真的把焦点转给按钮**，所以「点完还有没有焦点」在这个环境里天然测不到（那样写就是假绿）。因此改盯可证伪的点：

### 32.2 两条数据迁移（都是「只复制、不覆盖、不删源」）

**第 1 条：旧位置 → 新位置。**
0.4.2 及以前的稿子放在 `<外部私有>/bookcase`，**没有 `xinjian` 这一层**；0.4.3 起变成 `<外部私有>/xinjian/bookcase`。升级后第一次 `refreshDirs()` 会把旧目录里的稿子复制过来。

这条是**打包前在真机上发现的**：装机后查文件系统，发现 `files/bookcase/未命名.c` 还在旧位置，而新代码根本不看那儿——不补这一步，你升级完第一次打开书架会是空的。**这不是丢稿，是路径换了**，但用户看到的只有一个空书架，等价于丢稿。

**第 2 条：私有无权限 → 公共有权限。**
用户去系统设置开了「所有文件访问」再回来，`onResume` 发现「现在有权限」且「之前用的是私有目录」，就把私有目录的稿子复制到 `/sdcard/xinjian/bookcase/`。触发条件是 `nowPublic && !wasPublic`，用的是 `isPublic()`——它看的是 `dir` 的**实际位置**，不是「现在有没有权限」。这两个答案在用户刚开完权限、还没 `refreshDirs` 的那一瞬间是不同的，而判断必须基于「之前的目录在哪」。
